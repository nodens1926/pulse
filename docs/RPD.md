## 1. Problem Statement

Сотрудники корпоративных сетей тратят до 20% рабочего времени на поиск внутренней информации: документации, инструкций, вики-страниц, тикетов и файлов. Стандартный поиск по корпоративным ресурсам либо отсутствует, либо ищет только по точным ключевым словам, не понимая смысл запроса. В результате сотрудники не находят нужное, дублируют работу и теряют продуктивность.

---

## 2. Target Audience

**Первичная аудитория:**  
Технические специалисты (разработчики, DevOps, аналитики), работающие с внутренней документацией и базами знаний.

**Вторичная аудитория:**  
Менеджеры и сотрудники поддержки, которым нужен быстрый доступ к корпоративным регламентам и инструкциям.

**Покупатель:**  
CTO / IT-директора малых и средних компаний, которые ищут self-hosted решение без публикации данных в облако.

---

## 3. Value Proposition

Pulse Search — это self-hosted поисковый движок для корпоративных сетей с гибридным ранжированием: быстрый TF-IDF + точный SBERT.

**Ключевые преимущества:**
- **Гибридный поиск:** Сочетание скорости TF-IDF и семантической глубины SBERT — понимает смысл запроса, а не только ключевые слова.
- **Локальный контроль:** Все данные остаются внутри корпоративной сети. Разворачивается через Docker за несколько минут.
- **Открытый исходный код:** Не требует лицензионных платежей, легко кастомизируется под внутренние процессы.
- **Доступность:** Поддержка русского и английского языков «из коробки».

## 5. User Stories

**Формат:** «Как <роль>, я хочу <действие>, чтобы <ценность>».

1. **Как разработчик**, я хочу найти документацию по функции в внутренней вики по смыслу запроса, чтобы не тратить время на ручной просмотр страниц.
2. **Как аналитик**, я хочу искать по тикетам и инструкциям, чтобы быстро находить ответы на рабочие вопросы.
3. **Как IT-директор**, я хочу развернуть поиск внутри корпоративной сети, чтобы данные не покидали контур компании.
4. **Как администратор**, я хочу добавить новый сайт в индекс через админ-панель, чтобы сотрудники могли искать по нему.
5. **Как сотрудник поддержки**, я хочу видеть похожие страницы рядом с результатом, чтобы быстрее находить нужный регламент.

## 7. Технические требования

**Стек:**
- **Backend:** Python 3.11, FastAPI, Celery, SQLAlchemy
- **Поиск и NLP:** TF-IDF (scikit-learn), SBERT (sentence-transformers), pymorphy3, spaCy
- **Базы данных:** PostgreSQL (данные, инвертированный индекс), Redis (очередь задач)
- **Frontend:** React, TailwindCSS, Vite
- **Инфраструктура:** Docker, Docker Compose, Nginx
- **CI/CD (в планах):** GitHub Actions, pytest, ruff, black
- **Миграции (в планах):** Alembic

**Архитектура:**
Пользователь → Nginx + React → FastAPI → Celery (Redis) → Crawler → Parser → Indexer → PostgreSQL
